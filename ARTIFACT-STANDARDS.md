# Artifact Standards

## Principle
Choose the format based on how the artifact is used.

| Need | Preferred format |
|---|---|
| tracker/register/calculation/dashboard | XLSX |
| formal narrative/template/report | DOCX |
| executive/steering presentation | PPTX |
| playbook/checklist/reference | Markdown |
| machine-readable sample data | CSV where useful |

## Every reusable artifact needs
- purpose and intended audience;
- when to create/use;
- owner;
- update cadence;
- field/section instructions;
- example/sample;
- validation checks;
- version/date where appropriate.

## Spreadsheet standards
Use clear input/calculated fields, freeze panes, filters/tables, formulas rather than manually typed results, sensible validation, instructions sheet and sample data. Avoid decorative complexity.

## Document standards
Use clear heading hierarchy, concise instructions/placeholders and worked examples. Do not make templates look “complete” when important project decisions are still unknown.

## Presentation standards
One message per slide, executive-friendly summaries, decisions/risks visible, details in appendix where appropriate.

## Examples
Fictional/sample project data must be labeled **illustrative** and must not be presented as real employer/customer data.
